# 0001. 원본에서 계승하지 않은 것

- 상태: 확정
- 날짜: 2026-09-18

## 배경

`khmass-liturgy/pb` 의 단일 파일 구현을 재구축하면서, 기능은 같게 가져가되
그대로 옮기면 안 되는 구현 방식 네 가지를 확인했다.

## 결정

### 1. 브라우저에서 공개 CORS 프록시를 쓰지 않는다

원본은 뉴스 RSS·협회 게시판·Yahoo 시세를 브라우저에서 직접 긁으면서
`api.codetabs.com` · `api.allorigins.win` · `api.cors.lol` · `corsproxy.io`
네 곳을 로테이션했다.

- 제3자 서비스가 죽으면 패널이 통째로 빈다.
- 사용자의 요청이 제3자를 거친다.

외부 사이트 수집은 전부 GitHub Actions 에서 끝내고, 브라우저는 우리가 커밋한
JSON 만 읽는다. `src/lib/data-client.ts` 에 프록시 폴백을 두지 않은 이유다.

### 2. 브라우저에 GitHub PAT 를 저장하지 않는다

원본에는 '이달의 질병' 을 관리자가 화면에서 편집해 저장소에 커밋하는 기능이
있고(`publishPicks`, `PICK_TOKEN_KEY`), 이를 위해 개인 액세스 토큰을
`localStorage` 에 넣는다. 토큰이 유출되면 저장소 쓰기 권한이 그대로 넘어간다.

이 기능은 재현하지 않는다. 발행은 저장소를 직접 편집하거나
`workflow_dispatch` 로 처리한다.

### 3. 승인 명단을 공개 JSON 으로 두지 않는다

원본은 유료서비스 승인 화이트리스트를 `premium/approved.json` 에 전화번호·이메일
그대로 공개한다. 누구나 받아볼 수 있는 개인정보다.

유료서비스는 지금 단계에서 자리만 잡고(`AuthAdapter` 인터페이스),
실제 인증·승인 확인은 서버에서 한다. 공개 파일에 개인 식별자를 두지 않는다.

### 4. 구글 뉴스 RSS 를 쓰지 않는다

- 날짜: 2026-09-22 (뉴스 탭 작업 중 추가)

원본은 '해외 양계질병' 카드와 채널 탭의 기사를 구글 뉴스 RSS 에서 받았다.
거기서 오는 주소는 `news.google.com/rss/articles/CBMi...` 형태인데,
**원문으로 풀리지 않는다.** 서버에서 리다이렉트를 끝까지 따라가도 구글에
머무는 것을 확인했다(브라우저에서만 스크립트로 넘어간다). 제목을 누른
사용자는 기사가 아니라 구글 중간 페이지를 보게 된다.

같은 사건을 다룬 서로 다른 매체 기사가 중복으로 올라오는 문제도 있었다.

대신 매체 피드를 직접 읽는다. 주소가 곧 기사이고, 매체명·발행시각이 정확하다.
해외 양계는 The Poultry Site(질병 사전과 같은 출처), 일반 뉴스는 연합뉴스·
아시아경제다.

## 영향

원본과 기능은 같지만, 뉴스·게시판 패널은 수집 주기만큼 늦다(실시간이 아니다).
이달의 질병 편집 UI 는 없다. 뉴스의 매체 구성은 원본과 다르다 — 구글 뉴스로
받던 자리를 각 매체 피드로 채웠다.
